- やったこと（変更したファイル・設定・処理、または設計した取得方法）：app/config.pyのRAG_TOP_Kを1/5/10と変更した。
比較した質問と、固定した条件（モデル・対象資料など）：uv run python -m app.agent --trace "第2回の説明では、LoRAは何を固定し何を 学習しますか？QLoRAは何を加えますか？"

- 結果（変更前後の回答・根拠、--traceの出力、時間・トークン数・生成API推定費用など）：
(RAG_TOP_K=1)
* **LoRA**
  * **何を固定するか**：元の重み（$W$）を固定し、学習しません（第2回・PDF p.52）。
  * **何を学習するか**：小さな行列 $A$・$B$（細長い2つの行列の積で変化分を表す低ランクの「差分」）だけを学習します（第2回・PDF p.52）。
* **QLoRA**
  * LoRAの仕組み（元の重みを固定し、差分の行列だけを学習する）に加えて、**元の重みを4bitに圧縮（数値を粗く保存）すること**を加えます（第2回・PDF p.52）。

(RAG_TOP_K=5)
- **LoRA**
  - **固定するもの：** 元の重み（本体）は固定して学習しません（第2回・PDF p.52）。
  - **学習するもの：** 細長い2つの小さな行列の積（低ランク）で表される変化分（差分）の行列だけを学習します（第2回・PDF p.51, p.52）。
- **QLoRA**
  - LoRAの手法に加えて、**元の重みを4bitに圧縮**（数値を粗く保存）するという工夫が加えられています（第2回・PDF p.51, p.52）。これにより、さらに少ないメモリで大きなモデルの調整が可能になります。

(RAG_TOP_K=10)
* **LoRA**
  * **固定するもの**: 元の重み（本体）は固定して学習しません。（第2回・PDF p.52）
  * **学習するもの**: 細長い2つの小さな行列の積（低ランクの差分）である、小さな追加部分（行列 A・B）だけを学習します。（第2回・PDF p.51, 52）
* **QLoRA**
  * **加える（変更する）もの**: LoRAの仕組みに加えて、**元の重みを4bitに圧縮**（数値を粗く保存）します。（第2回・PDF p.51, 52）

- 改善した例と、残る失敗・制約：
最初に設定していたRAG_TOP_K=5が一番性能よく感じる。他の1/10の場合にはどちらも内容的に大きく問題はないが、若干文章が適切でないところがある。

- 気づき・疑問：
